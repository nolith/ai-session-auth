# SSH access for agents

`geas ssh` lets an agent log in to SSH hosts you name, for a few hours, as
the user `agent`, with a key of its own and a certificate you sign with an
agent CA, a key on a YubiKey. Each grant asks for the YubiKey's FIDO2 PIN
and a touch, at your terminal.

```bash
geas ssh enroll yk-blue                           # once per YubiKey
geas ssh list-cas                                 # the agent CAs, and which are plugged in
geas ssh name claude                              # the agent's name, claude-<workspace>
geas ssh grant claude-myproject transcoder --for 2h
geas ssh show claude-myproject                    # key ID, serial, validity, principals
geas ssh show                                     # every agent with a key
geas ssh drop claude-myproject                    # delete its key and certificate
```

## Agent names

An agent's name is `<tool>-<workspace>`: the tool, such as `claude` or
`opencode`, and the name of the terminal multiplexer workspace it runs in,
as the `herdr` CLI reports it, in lower case with dashes.
`geas ssh name TOOL` prints it.

When `AGENT_SSH_NAME` already names an agent of that tool, that is the
name, and `herdr`, which a sandbox may keep out of reach, is not needed.
`geas ssh name` alone prints `AGENT_SSH_NAME`.

## Granting access

`geas ssh grant AGENT HOST... [--for DURATION] [--ca YK-NAME]`:

- Each agent has its own ed25519 key, without a passphrase, in
  `$XDG_STATE_HOME/geas/agents/<name>` (`~/.local/state/geas/agents/` by
  default), generated by its first grant. Every grant signs that key again
  and atomically replaces its certificate, `id_ed25519-cert.pub`. The
  directories are mode 700, the files mode 600.
- The certificate's principals are `host:<host>` for each host, a short
  name of lower-case letters, digits and dashes.
- It is valid from 5 minutes ago, for hosts whose clock runs behind, for
  `--for`: from 1 minute to 12 hours, such as `30m` or `2h`, 4 hours by
  default.
- It carries no option but `permit-pty`: no forwarding of any kind.
- It is signed with the agent CA whose YubiKey is plugged in, matched by
  the serial number `ykman list --serials` reports; with several plugged
  in, `--ca` picks one.
- `grant` refuses to run without a terminal on stdin and stderr, and inside
  a session (`GEAS_SESSION_DIR` set): the PIN and the touch come from you,
  never from a prompt an agent triggered. `SSH_ASKPASS` is not used.

The key alone opens nothing on a host that accepts only certificates for
`agent`: what limits an agent is its certificate's lifetime, at most 12
hours. `geas ssh drop` deletes both.

## Agent CAs

The agent CAs are listed in `/etc/agent-grant/cas`, then in
`$XDG_CONFIG_HOME/geas/cas` (`~/.config/geas/cas`), one line each:

```text
<serial> <yk-name> <handle path>
```

Other lines and `#` comments are skipped, and the first CA of a name wins.
A handle is the CA key's file, useless without its YubiKey.

`geas ssh enroll YK-NAME` creates an agent CA on the one YubiKey plugged in.
The YubiKey must already have a FIDO2 PIN and support FIDO2 credProtect
(firmware 5.2 and later). The CA is a non-resident `ed25519-sk` key
(`ecdsa-sk` without Ed25519 support) that asks for the PIN at every
signature (`verify-required`, application `ssh:agent-ca`). Its handle goes
to `$XDG_STATE_HOME/geas/agent-ca/<yk-name>`.

`enroll` prints the serial, the public key and the handle's path, and
nothing else: add the line to a CA list to sign with it, and the public key
to the hosts. Like `grant`, it refuses without a terminal and inside a
session.

## In a session

With `{ "type": "ssh" }` among the providers, a session names its agent
when it starts: the tool is the base name of the first word after
`geas run --`, and the name is found as `geas ssh name` finds it, outside
the sandbox. The harness gets it as `AGENT_SSH_NAME`. When there is no
name, the provider fails, and the session starts all the same.

Once the harness runs, the provider checks that the agent has a key and a
certificate valid now, and copies both into the session directory with an
`ssh/config`. The agent connects with:

```bash
ssh -F "$GEAS_SESSION_DIR/ssh/config" transcoder 'uptime'
```

That configuration replaces `~/.ssh/config` entirely: user `agent`, the
session's key and certificate only (`IdentitiesOnly yes`,
`IdentityAgent none`), no agent forwarding, no shared connections,
`BatchMode yes`, and your own `~/.ssh/known_hosts`, strictly, without
adding to it. A sandbox needs to grant only the session directory: every
agent's key, in `$XDG_STATE_HOME/geas/agents`, is among the session's
protected paths.

Without a valid certificate, the `ssh` marker is `failed`, with what to do:
`ask the human: geas ssh grant <name> <host>`. Every 3 seconds the provider
checks the agent's directory, a `stat` of three files, and reads it again
when one changed:

- a grant made while the session runs reaches the agent within seconds and
  turns the marker `ready`;
- when the session's certificate expires, or `geas ssh drop` deletes it,
  the session's copies and `ssh/config` go, and the marker turns `failed`
  again.

There is nothing to revoke: a certificate expires on its own, within 12
hours.

Inside a session, `geas ssh show` and `geas ssh show <its own name>` read
the session's copy, since a sandbox keeps the agents' directory out of
reach, and also print the configuration's path.

## Hosts

geas does not set up hosts. A host lets an agent in when its `sshd`:

- trusts the agent CAs' public keys for the user `agent`
  (`TrustedUserCAKeys`);
- accepts the principal `host:<its host name>` for that user, with an
  `AuthorizedPrincipalsFile` listing it;
- ideally has no authorized keys for `agent` at all.

## Requirements

`geas ssh` needs, on `PATH`:

- OpenSSH's own `ssh-keygen`, with FIDO2 support; macOS's
  `/usr/bin/ssh-keygen` has none;
- `ykman`, from yubikey-manager;
- `fido2-token`, from libfido2.

The Nix package wraps `geas` so that nixpkgs' `openssh`, `yubikey-manager`
and `libfido2` come first on its `PATH`, whatever yours has; a session's
harness gets your `PATH` back unchanged.
